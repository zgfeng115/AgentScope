# AgentScope 任务 7：SwiftUI 仪表盘设计

日期：2026-08-02  
状态：待规格复核

## 1. 目标

为 AgentScope 提供一个原生 macOS SwiftUI 主窗口，用于审计自动启动项、定时任务、登录项、Shell 启动来源和开发生态条目，并安全操作用户自己的 LaunchAgent。

仪表盘不把系统进程列表作为产品对象；进程采集不进入生产库存。项目归因和确定性审计结果进入统一详情展示，可选 AI 接口默认不联网。

## 2. 主窗口布局

主窗口采用 `NavigationSplitView` 的三层结构：

1. 左侧来源栏：`全部`、`项目视图`、`自动启动项`、`定时任务`、`登录项`、`Shell 启动`、`开发生态`、`需要关注`。
2. 中间服务列表：显示名称、来源、状态、PID、有效性和只读标记。
3. 右侧详情面板：显示服务的完整信息和可用操作。

窗口顶部提供刷新按钮和扫描状态。窗口需要适合 macOS 桌面使用，保持现有最小窗口尺寸 900×600。

## 3. 服务列表与筛选

列表支持：

- 按名称、标签、程序路径和配置路径搜索。
- 按来源和状态筛选。
- 按名称、来源或状态排序。
- 刷新后尽量保持当前选中服务；如果服务已消失，则清除选中项。
- 若未来通过诊断模式加载系统条目，系统条目始终显示只读标记；生产模式不加载它们。

列表不直接修改 `ServiceItem`。展示和筛选使用 ViewModel 的派生状态，采集结果作为不可变快照替换。

## 4. 详情面板

详情面板分为以下信息组：

- 概览：名称、来源、作用域、当前状态、PID、启用状态。
- 启动信息：配置路径、程序路径、参数、最近运行时间和时间精度。
- 有效性：有效/失效结果、签名分类、证据列表和归属信息。
- 操作历史：由 `LocalStore` 提供的操作记录。
- 操作区：根据来源、作用域和当前状态显示允许的操作。

时间精度必须沿用 `RunTimePrecision`，不能把推测时间显示为精确时间。未知值显示为“未知”，而不是伪造日期。

## 5. 数据流与组件边界

```text
Launchd / cron / periodic / shell / Login Item / ecosystem collectors
                       ├─> ProductionServiceInventory ─> DashboardViewModel
                       ┘                              │
                                                     ├─> SourceSidebar
                                                     ├─> ServiceListView
                                                     └─> ServiceDetailView
                                                            │
                                                  LaunchAgentController
```

### `ServiceInventory`

负责调用已有采集器、合并结果、去重并返回服务快照。单个采集器失败时保留其他采集器结果，并返回可展示的部分失败信息。

### `DashboardViewModel`

使用 `@MainActor` 管理：

- 当前快照、加载状态和扫描错误。
- 来源筛选、状态筛选、搜索文本和排序方式。
- 当前选中服务。
- 操作中的服务 ID 和操作错误。
- 刷新、操作后重新采集以及详情历史加载。

ViewModel 依赖协议注入的 inventory、controller 和 store，SwiftUI 视图不直接调用命令执行器或 Core Data。

### SwiftUI 视图

- `DashboardView`：组合导航栏、工具栏和三栏布局。
- `SourceSidebar`：来源筛选。
- `ServiceListView`：搜索、筛选后的服务列表。
- `ServiceRowView`：单行状态与证据摘要。
- `ServiceDetailView`：详情信息和操作按钮。
- `OperationConfirmationView`：执行用户服务操作前的影响范围确认。

## 6. 交互安全与异常状态

- 启动时显示扫描状态；扫描完成前列表显示进度占位。
- 没有条目时显示空状态和重新扫描按钮。
- 部分采集器失败时显示警告，但不丢弃成功采集的数据。
- 系统服务详情可以查看，但隐藏启动、停止、重启、启用、禁用和测试运行入口。
- 用户 LaunchAgent 操作在确认界面中显示目标服务、配置路径、作用域和备份说明。
- 操作期间禁用重复点击；完成后必须重新采集并更新详情。
- 控制器失败时显示可读错误，并保留操作前状态。
- 操作成功但状态后置校验失败时，界面显示“结果未确认”，不能显示为成功。

## 7. 测试策略

采用 ViewModel 单元测试为主，覆盖：

- 搜索、来源筛选、状态筛选和排序。
- 选中服务在刷新前后的保持与清除。
- 用户条目显示可用操作，系统条目不显示修改操作。
- 初始加载、空结果、部分失败和全量失败。
- 操作中的重复点击保护。
- 操作成功、控制器失败和后置状态未确认。
- 时间精度为 `Exact`、`Approximate`、`Unknown` 时的展示模型。

SwiftUI 视图通过 macOS target 编译验证；涉及系统窗口渲染的验证不依赖真实 launchd，使用注入的 fake inventory、controller 和 store。

## 8. 明确不在本任务内

- 自动触发云端 AI；仅保留可选、显式调用的分析接口。
- 系统 LaunchDaemon 的提权操作。
- plist 编辑器、日志查看器和备份恢复界面。
- 进程组停止、端口检测和实时事件时间线。

## 9. 验收标准

- 启动应用后能展示已有采集器返回的服务条目。
- 用户可以通过来源、状态和搜索条件快速定位条目。
- 点击条目后右侧显示完整详情和证据。
- 系统条目明确只读，不能从普通界面触发修改操作。
- 用户 LaunchAgent 操作会进入确认流程，并复用已完成的控制器。
- 刷新、错误、空状态和部分失败都有明确 UI。
- ViewModel 测试覆盖核心筛选和操作状态，项目全量测试通过。
